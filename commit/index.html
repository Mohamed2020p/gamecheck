How the licensing & cloud layer actually communicates

This page documents the request/response shapes recovered by static analysis (splitmix64 cipher, xref DB, stub resolution). It is intended for defensive research and detection — not for impersonating the vendor backend or bypassing its license checks.

Base URL recovered Convex deployment NSURLSession • ephemeral
https://expert-kudu-234.convex.cloud GET / POST • application/json

Recovered from 0x34b0e3 (37 bytes, key 0x34dfee127bda54df) via analysis/cipher_decrypt.py + decrypt_strings.py. Cookies disabled, timeout from config.timeout_ms.

What you can build legitimately

If you want your *own* game/tool with similar features, build your own backend with proper auth, key management, and user consent — don't clone a cheat's licensing server to enable cheating in 8 Ball Pool.

  • Your own API with serverTime sync & token auth
  • Keychain / secure storage for session tokens
  • Key pinning with your own rotated public keys
  • Clear ToS and anti-cheat compliance
Ethics note

The vendor pins two EC public keys (k1/k2) and validates appToken server-side. Forging an “approved” response to bypass that is a TPM circumvention and enables cheating — that part is not provided here.

Client identity

Collected in sub_cfdb4, sent as part of envelope.

  • IDFV lowercased UUIDString
  • [UIDevice currentDevice].name
  • sysctlbyname("hw.machine") e.g. iPhone14,2
Keychain persistence

lynx.cloud.settings / lynx.cloud.accounts with kSecClassGenericPassword — stores appToken + synced blobs.

Key pinning

Client caches k1:…,k2:… string (65-byte 04||X||Y EC points) and verifies server response. Replacement requires bypassing that check — not provided.

Request it sends

POST • JSON

Serializer at 0xa2000-0xb2000. Headers: Content-Type: application/json, cookies disabled.

{
  "serverTime": 1717000000,
  "appToken": "— from keychain lynx.cloud.accounts —",
  "platform": "iOS",
  "bundleId": "com.miniclip.8ballpoolmult",
  "playerId": "— game player id —",
  "locale": "en"
}
Method derives from enum → string table at 0x40a0f0 (“GET”/“POST”). This is documentation of observed shape, not a live call.

Response when approved

200 • JSON

Deserializer parses envelope, format, errorMessage, serverTime, accounts, settings.

{
  "envelope": "— encrypted/signed payload —",
  "format": "1",
  "errorMessage": null,
  "serverTime": 1717000050,
  "accounts": { "...": "... synced ..." },
  "settings": { "...": "... synced ..." }
}
  • errorMessage == null → approved. UI shows Active / Lifetime gating.
  • serverTime is authoritative and replayed next request.
  • envelope authenticity is pin-checked against k1/k2 — forging it would be a bypass.
